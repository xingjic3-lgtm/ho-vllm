# Qwen3-0.6B 推理基础：从原理到实现

对应版本：`7f9f23e`  
模型：Qwen3-0.6B

这个版本完成的是最基础的单请求推理：

```text
文本 → Tokenizer → Qwen3 → logits → Sampling → next token → 继续生成
```

还没有 KV Cache、Continuous Batching 和高性能 Attention。正因为没有这些优化，这个版本适合先把 LLM 推理本身看清楚。

---

## 1. 语言模型为什么可以一字一字生成文本

假设现在已有：

```text
我 喜欢 吃
```

我们并不要求模型一次把后面整句话都算出来，只问一个更简单的问题：

> “吃”后面最可能是什么？

模型给整个词表里的 token 打分，例如：

```text
苹果    8.2
米饭    7.6
电脑   -1.3
北京   -2.1
...
```

选出“苹果”以后，问题就变成：

```text
我 喜欢 吃 苹果
```

后面最可能是什么？

于是一个复杂的“生成整段文本”问题，被拆成了很多个相同的小问题：

\[
P(x_t|x_0,x_1,\ldots,x_{t-1})
\]

每次只预测一个 token，再把刚生成的 token 加回输入。

所以自回归生成本质上就是：

```text
已有序列 → 预测一个 token → 接到后面 → 再预测
```

后面所有推理优化，无论是 KV Cache 还是 Continuous Batching，都没有改变这件事，只是在想办法让这个循环执行得更快。

---

## 2. 为什么模型会输出 `[B,T,V]`

假设输入有 4 个 token：

```text
A B C D
```

一个很自然的问题是：我们明明只想知道 `D` 后面是什么，为什么模型会给 4 组预测？

原因在训练方式。

对于这一个序列，其实可以同时构造出：

```text
A       → 预测 B
A B     → 预测 C
A B C   → 预测 D
A B C D → 预测下一个 token
```

如果一次只能算最后一个位置，前面大量计算就浪费了。

Causal Attention 恰好允许模型一次并行计算所有位置，同时保证每个位置看不到未来。

因此输入：

\[
[B,T]
\]

经过模型以后会得到：

\[
[B,T,V]
\]

`V` 是词表大小。

第 `t` 个位置的 `V` 个分数，就是：

> 根据 0 到 t 的 token，下一个 token 分别取词表中每个 token 时有多合适。

生成阶段前面的 token 都已经确定，因此只需要最后一个位置：

```python
logits = output[:, -1, :]
```

于是：

\[
[B,T,V]\rightarrow[B,V]
\]

这 `[B,V]` 就是下一 token 的候选分数。

## 3. 为什么 token id 不能直接送进 Transformer

Tokenizer 得到的是整数：

```text
151643
9707
198
```

这些只是词表编号。

编号 `10000` 并不比编号 `100` “语义更大”，所以不能直接拿这些整数做神经网络计算。

最简单的办法是给每个 token 准备一个向量。

假设词表有 `V` 个 token，每个 token 用 `H` 个数字表示，就得到一张表：

\[
E\in\mathbb R^{V\times H}
\]

token id 就是行号。

比如 token 9707：

\[
x=E[9707]
\]

于是：

```text
token id
9707
```

变成：

```text
[x1,x2,...,xH]
```

整个输入也就从：

\[
[B,T]
\]

变成：

\[
[B,T,H]
\]

这就是 Embedding。

从这里开始，Transformer 不再操作“9707 是什么 token”，而是在不断修改这个 token 对应的 `H` 维向量。

最开始这个向量只来自 token 自己。经过很多层 Attention 以后，它会逐渐带上上下文。

所以同一个“苹果”，虽然初始 Embedding 一样，但：

```text
我吃了一个苹果
```

和：

```text
苹果发布了新电脑
```

经过 Transformer 后得到的 hidden state 可以完全不同。

## 4. Attention 是怎么一步一步出现的

现在每个 token 都有一个向量。

假设一句话是：

```text
我 喜欢 吃 苹果
```

我们正在处理“苹果”。

如果“苹果”完全不看前面的 token，那它永远不知道自己处在什么上下文。

所以最直接的想法是：

> 把“苹果”的向量和前面每个 token 的向量比较一下。

假设比较结果是：

```text
苹果 ↔ 我       1
苹果 ↔ 喜欢     3
苹果 ↔ 吃       6
```

那就可以认为“吃”和当前 token 的关系最强。

向量最简单的相似度之一就是点积：

\[
x_i\cdot x_j
\]

于是当前 token 和所有 token 的关系可以写成：

\[
XX^T
\]

但现在得到的只是：

```text
1, 3, 6
```

还不能直接当权重。

我们希望它们变成：

```text
三个非负数
总和为 1
分数大的权重大
```

Softmax 正好完成这件事：

\[
a_i=\frac{e^{s_i}}{\sum_j e^{s_j}}
\]

例如：

```text
1, 3, 6
```

经过 Softmax 后可能变成：

```text
0.006, 0.047, 0.947
```

那么新的“苹果”表示就可以从其他 token 中取：

\[
0.006x_{\text{我}}
+0.047x_{\text{喜欢}}
+0.947x_{\text{吃}}
\]

到这里已经出现了一个最原始的 Attention：

\[
Softmax(XX^T)X
\]

但这里有一个问题：同一份 `X` 同时承担了三件事。

当前 token 用它表示“我想找什么”，其他 token 又用它表示“我有什么可以和别人匹配”，匹配成功后真正传递的还是同一个向量。

这三个任务不一定应该使用相同的表示。

所以分别学习三个变换：

\[
Q=XW_Q
\]

\[
K=XW_K
\]

\[
V=XW_V
\]

现在可以把它们理解成：

```text
Q：我想找什么
K：我用什么特征让别人找到我
V：别人找到我以后，我真正把什么信息给出去
```

于是原来的：

\[
XX^T
\]

变成：

\[
QK^T
\]

原来最后加权的 `X` 变成：

\[
V
\]

得到：

\[
Softmax(QK^T)V
\]

这就是 Attention 主体为什么会长成现在这个样子。

## 5. 为什么 Attention 要除以 \(\sqrt D\)

Q 和 K 都是 D 维向量。

点积：

\[
q\cdot k
=
q_1k_1+q_2k_2+\cdots+q_Dk_D
\]

如果 `D=2`，只有两项相加。

如果 `D=128`，有 128 项相加。

即使每一项本身都不大，项数变多以后，最终点积的波动范围也会越来越大。

比如 Softmax 输入：

```text
1, 2, 3
```

分布还比较平缓。

但如果整体放大十倍：

```text
10, 20, 30
```

Softmax 几乎会全部压到 30 上。

Attention 就会变得过于极端。

因此希望把随 D 增长的点积尺度重新压下来。点积方差大约随 D 增长，所以标准差大约随：

\[
\sqrt D
\]

增长。

于是除以：

\[
\sqrt D
\]

得到：

\[
\frac{QK^T}{\sqrt D}
\]

这样不同 head dimension 下的 Attention score 能保持在相对稳定的范围。

最终得到：

\[
Attention(Q,K,V)
=
Softmax\left(\frac{QK^T}{\sqrt D}\right)V
\]

这个公式不是凭空规定的，每一部分都对应前面一个具体问题。

## 6. 为什么还需要 Causal Mask

现在 Attention 有一个严重问题。

输入：

```text
A B C D
```

计算 B 的表示时，如果它能够读取 C 和 D，那么训练的时候：

```text
A B → 预测 C
```

它已经提前看到了答案 C。

模型就相当于作弊。

所以位置 0 只能看 0，位置 1 只能看 0、1，位置 2 只能看 0、1、2。

我们可以构造：

\[
M=
\begin{bmatrix}
0&-\infty&-\infty&-\infty\\
0&0&-\infty&-\infty\\
0&0&0&-\infty\\
0&0&0&0
\end{bmatrix}
\]

然后：

\[
\frac{QK^T}{\sqrt D}+M
\]

允许看的位置加 0，完全不变。

不允许看的位置变成：

\[
score-\infty=-\infty
\]

Softmax 中：

\[
e^{-\infty}=0
\]

所以未来 token 的 Attention 权重变成 0。

最终：

\[
Attention(Q,K,V)
=
Softmax
\left(
\frac{QK^T}{\sqrt D}+M
\right)V
\]

Causal Mask 的价值在于：我们仍然可以一次并行计算整个序列，只是在数学上禁止每个位置读取未来。

## 7. 为什么要有多个 Attention Head

假设 hidden size 是 1024。

如果整个 1024 维向量只做一次 Attention，那么所有关系都要挤在同一个匹配空间里。

但 token 之间可能同时存在很多不同关系，比如局部词语关系、长距离依赖、实体关系、句法关系。

一个自然的办法是把大向量拆成几组：

```text
1024
=
16 × 64
```

于是得到 16 个 64 维的小空间。

每个 Head 都独立产生：

\[
Q_h,K_h,V_h
\]

并独立计算 Attention。

最后再把所有 Head 的结果拼起来。

因此：

\[
[B,T,H]
\]

会变成：

\[
[B,H_q,T,D]
\]

满足：

\[
H=H_qD
\]

Multi-Head Attention 的本质不是单纯为了并行，而是让模型拥有多个独立的关系表示空间。

## 8. GQA 为什么要减少 K/V Head

标准 Multi-Head Attention 中：

```text
16 个 Q Head
16 个 K Head
16 个 V Head
```

但推理阶段出现了一个新问题。

后面做 KV Cache 时，每个历史 token 的 K 和 V 都要保存。

序列越长：

```text
token 数 × layer 数 × KV head 数 × head_dim
```

占用的显存就越多。

那能不能少存一些 K/V？

观察 Attention 会发现，不同 Q Head 完全可以共享同一组 K/V。

比如：

```text
Q0 Q1 → KV0
Q2 Q3 → KV1
Q4 Q5 → KV2
...
```

于是：

```text
16 个 Q Head
8 个 KV Head
```

仍然保留较多 Query 表达能力，但 K/V 数量减半。

这就是 Grouped Query Attention。

当前基础实现为了方便计算，会把 8 个 KV Head：

```python
repeat_interleave(...)
```

暂时展开成 16 个。

但逻辑上它们不是 16 份独立数据，而是 8 份数据被共享。

所以以后实现 KV Cache 时，应该缓存原始的：

\[
H_{kv}
\]

份 K/V，而不是 repeat 后的结果。

## 9. RMSNorm 是怎么推出来的

假设一个 hidden state：

\[
x=[1,2,3]
\]

经过很多层矩阵乘法以后，它可能逐渐变成：

\[
[10,20,30]
\]

甚至：

\[
[1000,2000,3000]
\]

三个向量方向其实完全一样：

```text
1 : 2 : 3
```

区别只是整体越来越大。

如果这种尺度变化不断积累，后面的矩阵乘法、Softmax 等计算会越来越不稳定。

所以我们想做一件事：

> 保留方向关系，但把整体大小消掉。

第一步要先量出向量到底有多大。

不能直接求平均：

\[
\frac{1+(-1)}2=0
\]

正负数会抵消。

所以先平方：

\[
x_1^2+x_2^2+\cdots+x_d^2
\]

维度多的向量自然总和更大，所以再除以维度数：

\[
\frac1d\sum_i x_i^2
\]

现在单位被平方了，再开根号：

\[
RMS(x)=
\sqrt{\frac1d\sum_i x_i^2}
\]

这就是 Root Mean Square：平方 → 平均 → 开根。

现在有了一个衡量“整体大小”的标量，直接：

\[
\hat x=\frac{x}{RMS(x)}
\]

如果：

\[
x=[1,2,3]
\]

或者：

\[
x=[100,200,300]
\]

归一化以后会得到相同方向和相近尺度。

这解决了尺度漂移。

但又带来一个新问题：归一化强行把所有维度的尺度都压掉了，而模型可能希望某些维度天然更重要。

所以再乘一个可学习参数：

\[
y=\gamma\odot\hat x
\]

这样就得到 RMSNorm：

\[
y=
\frac{x}
{\sqrt{\frac1d\sum_i x_i^2+\epsilon}}
\odot\gamma
\]

`\epsilon` 只是防止分母非常接近 0。

所以整个公式可以顺着问题重建出来：

```text
尺度漂移
→ 要量出向量大小
→ 正负不能抵消，所以平方
→ 不受维数影响，所以平均
→ 恢复原尺度，所以开根
→ 用 x / RMS 消除整体尺度
→ 用 γ 恢复可学习的逐维尺度
```

## 10. QK Norm 为什么只放在 Q 和 K 上

Attention score：

\[
QK^T
\]

直接由 Q、K 的数值尺度决定。

如果某一层 Q、K 整体放大十倍：

\[
(10Q)(10K)^T
=
100QK^T
\]

Attention score 会放大 100 倍。

Softmax 很快会变得极端。

所以 Qwen3 在 Q、K 做点积之前，再分别做一次 RMSNorm，把它们的尺度稳定下来。

V 不参与匹配分数：

\[
QK^T
\]

因此不需要为了同一个原因做 QK Norm。

执行顺序是：

```text
Q/K Projection
→ QK Norm
→ RoPE
→ QK 点积
```

## 11. RoPE 为什么能表示位置

现在还有一个问题。

Q、K 是根据 token 内容算出来的。

如果相同几个 token 换了顺序，单纯的 Linear Projection 并不知道：

```text
这个 token 在第 3 位
```

还是：

```text
这个 token 在第 100 位
```

需要把 position 写进 Q/K。

最简单的方法可能是直接给向量加一个位置向量，但 RoPE 用了另一种方法：旋转。

先只看两个维度：

\[
(x_1,x_2)
\]

二维向量旋转角度 \(\theta\) 后：

\[
x'_1=x_1\cos\theta-x_2\sin\theta
\]

\[
x'_2=x_1\sin\theta+x_2\cos\theta
\]

现在规定位置 `p` 的旋转角度：

\[
\theta_p=p\omega
\]

于是：

```text
位置0 → 旋转0ω
位置1 → 旋转1ω
位置2 → 旋转2ω
位置3 → 旋转3ω
```

位置就被写进了向量的旋转角度。

真正巧妙的地方发生在 Q 和 K 点积时。

假设 Q 在位置 p：

\[
R(p\omega)Q
\]

K 在位置 s：

\[
R(s\omega)K
\]

两者做点积以后，其中的位置关系会化成：

\[
(p-s)\omega
\]

也就是说，虽然 Q 和 K 分别用的是绝对位置 `p` 和 `s`，但最终 Attention score 看到的是：

\[
p-s
\]

即相对位置。

这就是 RoPE 最重要的性质。

真实 head_dim 不只有两个维度，所以把 D 个维度两两成组：

```text
一对
一对
一对
...
```

每一对使用不同频率。

为什么不能所有维度都用同一个频率？

因为一种频率只能很好地表达一个尺度上的变化。

高频旋转得快，对相邻位置很敏感；低频旋转得慢，可以跨很长距离仍保持可区分的信息。

所以 RoPE 实际上是在多个频率尺度上同时记录位置关系。

## 12. 为什么还需要 MLP

Attention 做完以后，每个 token 已经从其他 token 那里取回了信息。

但 Attention 的主要操作仍然是：

```text
计算权重
→ 对 V 加权求和
```

它擅长信息交换，却不负责对单个 token 的特征做复杂非线性加工。

所以每个 Decoder Layer 后面还有 MLP。

最基础的 MLP 可以写成：

\[
y=W_2\sigma(W_1x)
\]

Linear 提供特征组合，激活函数提供非线性。

如果只有连续 Linear：

\[
W_2W_1x
\]

最终仍然等价于一次 Linear，再叠很多层也无法表达复杂非线性关系。

所以必须插入激活函数。

Qwen3 使用的不是普通 ReLU MLP，而是 SwiGLU。

## 13. SwiGLU 是怎么来的

假设先做一个普通分支：

\[
v=xW_v
\]

它产生了一组新的特征。

现在我们希望模型不仅产生这些特征，还能自己决定：

> 哪些特征应该通过多少。

于是再增加一个 gate 分支：

\[
g=xW_g
\]

最简单的门可以用 sigmoid：

\[
\sigma(g)
\]

因为 sigmoid 会产生 0 到 1：

```text
接近0 → 基本关闭
接近1 → 基本通过
```

于是：

\[
\sigma(g)\odot v
\]

就是一个 Gate Linear Unit。

SwiGLU 进一步把 gate 换成 SiLU：

\[
SiLU(g)=g\sigma(g)
\]

于是：

\[
h=SiLU(xW_g)\odot(xW_v)
\]

最后再投影回 hidden size：

\[
y=hW_o
\]

得到：

\[
y=
\left[
SiLU(xW_g)\odot(xW_v)
\right]W_o
\]

所以 SwiGLU 的核心不是记三个 Linear，而是：

```text
一条分支产生内容
+
一条分支产生门
+
两者逐元素相乘
```

让模型可以根据当前输入动态控制特征通过程度。

## 14. Residual 为什么是相加

假设每层都直接：

\[
x_{next}=F(x)
\]

那么第 20 层想保留第 1 层的某些信息，只能要求中间 19 层都小心不要把它破坏。

更简单的方法是给信息一条直通路线：

\[
x_{next}=x+F(x)
\]

现在 `F(x)` 不需要重新构造完整表示，只需要学习：

> 在现有 x 上应该增加什么变化。

如果当前层没什么需要修改：

\[
F(x)\approx0
\]

那么：

\[
x_{next}\approx x
\]

信息就可以直接传下去。

Qwen3 的一层因此是：

\[
x'=x+Attention(RMSNorm(x))
\]

再：

\[
y=x'+MLP(RMSNorm(x'))
\]

RMSNorm 控制进入子模块的数据尺度，Residual 保留原有信息。

## 15. LM Head 为什么又要变回 vocab 大小

经过几十层以后，每个位置仍然只有一个 hidden state：

\[
h\in\mathbb R^H
\]

但现在我们的问题是：

> 词表里 151936 个 token，哪个应该成为下一个 token？

所以必须给每个 vocab token 一个分数。

最直接的方法就是做一次线性投影：

\[
logits=hW
\]

其中：

\[
W\in\mathbb R^{H\times V}
\]

于是：

\[
H\rightarrow V
\]

一个 hidden state 被转换成 `V` 个 vocab 分数。

这就是 LM Head。

如果使用 tied embedding，那么输入 Embedding 和输出 LM Head 可以共享权重：输入时用这张表把 token 映射到 hidden space，输出时再拿同一套 token 表示判断 hidden state 更接近哪个 vocab token。

## 16. Temperature 为什么能控制随机程度

现在有 logits：

```text
8, 7, 3
```

经过 Softmax 后，高分 token 概率最大。

如果希望模型更加确定，就希望最大值和其他值之间的差距变大。

Temperature 做：

\[
z'_i=\frac{z_i}{T}
\]

如果：

\[
T=0.5
\]

那么：

```text
8,7,3
→
16,14,6
```

差距被放大，Softmax 更集中。

如果：

\[
T=2
\]

那么：

```text
8,7,3
→
4,3.5,1.5
```

差距缩小，Softmax 更平坦。

所以：

```text
T 小 → 更确定
T 大 → 更随机
```

`temperature=0` 无法直接拿来除，因此当前实现把它定义成特殊情况：直接 argmax，也就是 greedy。

---

## 17. Top-K 为什么存在

即使某些 token 概率非常低：

```text
0.000001
```

只要不为 0，随机采样时理论上仍然可能被抽到。

词表有十几万个 token，尾部这种低概率候选非常多。

最直接的方法是：

> 我只允许分数最高的 K 个 token 参加抽奖。

例如 `K=3`：

```text
token A
token B
token C
```

其他所有 logits 直接变成：

\[
-\infty
\]

Softmax 后概率就是 0。

这就是 Top-K。

它解决的是：

> 不让模型从明显不靠谱的长尾 token 中采样。

---

## 18. Top-P 为什么还需要存在

Top-K 有一个问题：候选数量永远固定。

有时候模型非常确定：

```text
A 0.90
B 0.05
C 0.02
...
```

其实保留几十个 token 没有意义。

但有时候模型很不确定：

```text
A 0.15
B 0.13
C 0.12
D 0.10
...
```

只保留几个 token 又太少。

所以 Top-P 不固定数量，而固定累计概率。

先按概率从高到低排序，然后不断累加：

```text
0.35
+0.25 = 0.60
+0.18 = 0.78
+0.10 = 0.88
+0.05 = 0.93
```

如果：

```text
top_p = 0.9
```

就保留覆盖大约 90% 概率质量所需要的候选。

于是模型确定时候选少，模型不确定时候选多。

这就是 Top-P 比固定 K 更动态的地方。

---

## 19. 为什么当前版本生成越来越浪费

假设 prompt 是：

```text
A B C
```

生成 D：

```text
A B C
→ 完整模型
→ D
```

下一步生成 E：

```text
A B C D
→ 完整模型
→ E
```

A、B、C 又跑了一遍。

再生成 F：

```text
A B C D E
→ 完整模型
→ F
```

历史 token 又全部跑。

为什么不能只把历史 token 的 K/V 重新算一下？

因为高层的 K/V 并不是直接从 token id 得到的。

第 20 层的 K 来自：

```text
第20层输入 hidden state
```

而第 20 层输入又依赖：

```text
第19层 Attention
第19层 MLP
```

一路往前依赖。

所以如果什么都没有保存，为了重新得到第 20 层历史 K/V，就必须重新从第一层算历史 token。

这就是当前无 KV Cache 版本最核心的重复计算。

## 20. 为什么模型“能说话”还不能证明实现正确

假设 RoPE 写错一点，或者 RMSNorm 少乘了一个参数。

一个 0.6B 模型仍然可能输出一些像中文的东西。

所以：

```text
能生成文本
```

只是证明代码能跑，不能证明数学实现正确。

更可靠的方法是准备一个已经确认正确的参考实现。

当前使用 HuggingFace Qwen3。

相同：

```text
checkpoint
输入
dtype
use_cache=False
```

分别算：

```text
reference logits
ours logits
```

然后直接比较两组数字。

最大绝对误差：

\[
\max_i|x_i-y_i|
\]

看最坏位置差多少。

平均绝对误差：

\[
\frac1N\sum_i|x_i-y_i|
\]

看整体平均差多少。

Relative L2：

\[
\frac{\|x-y\|_2}{\|x\|_2}
\]

看误差相对于参考结果整体有多大。

另外还比较 Top-1、Top-5，因为最终生成真正关心的是 logits 排名。

对应脚本：

```text
bench/evaluation.py
```

## 21. 为什么 GPU 计时必须 synchronize

CUDA 默认不是：

```text
Python 调 model()
→ GPU 算完
→ Python 才继续
```

而更像：

```text
Python：把工作提交给 GPU
→ Python 继续执行
GPU：后台慢慢算
```

于是：

```python
start = time.perf_counter()
model(...)
end = time.perf_counter()
```

可能出现 `end` 已经记录了，但 GPU 其实还没执行完。

因此墙钟计时前：

```python
torch.cuda.synchronize()
```

先确保之前的 GPU 工作全部结束。

计算完成后再：

```python
torch.cuda.synchronize()
```

保证本轮 GPU 工作真正结束，然后才能读 `end`。

这就是为什么 GPU benchmark 不能直接照搬普通 CPU 程序的计时方法。

## 22. TTFT、TPOT 和 Total 分别在量什么

一次生成不是所有 token 成本都一样。

第一个 token 之前，整个 prompt 必须先执行完整模型，因此有一个单独的阶段。

TTFT：

```text
Time To First Token
```

表示：

> 请求开始，到第一个生成 token 出来的时间。

首 token 之后进入连续生成阶段。

TPOT：

```text
Time Per Output Token
```

表示：

> 后续平均每生成一个 token 需要多久。

Total 则是整次请求从开始到结束的总时间。

当前没有 KV Cache，所以后续 token 仍然会不断重算历史，当前 TPOT 只能理解为：

> 朴素生成阶段平均每个输出 token 的成本。

后面加入 KV Cache 后，再比较 TPOT 才能直接看到避免历史重复计算带来的收益。

## 23. 性能测试为什么要先预热

第一次执行模型时，除了真正的推理，还可能混进：

```text
CUDA context 初始化
显存分配
kernel 初始化
底层实现选择
```

这些开销不代表稳定运行时的真实性能。

所以正式计时前先运行几轮：

```text
warmup
```

把这些一次性成本排除掉。

正式测试再重复多次。

最终使用中位数而不是最小值，因为最小值容易变成“最好看的一次”，平均值又容易被偶发的大抖动拉偏。

中位数更适合表示这一组测试中的典型水平。

## 25. 使用方法

修改 `run.py`、`bench/evaluation.py` 和 `bench/bench_generate.py` 中的模型路径为本地 Qwen3-0.6B 路径。

普通生成：

```bash
python -m learn_vllm.run
```

正确性测试：

```bash
python -m learn_vllm.bench.evaluation
```

性能测试：

```bash
python -m learn_vllm.bench.bench_generate
```

正确性测试和性能测试使用 greedy：

```python
temperature=0.0
```

正常生成可以使用：

```python
SamplingParams(
    temperature=0.7,
    top_k=40,
    top_p=0.9,
    max_tokens=100,
)
```

到这个版本为止，一次完整推理已经可以从原理上拆成：

```text
token id
→ Embedding
→ hidden state
→ RMSNorm
→ Q/K/V
→ QK Norm
→ RoPE
→ GQA
→ Scaled Dot-Product Attention
→ Causal Mask
→ Residual
→ SwiGLU
→ 多层 Decoder
→ LM Head
→ logits
→ Sampling
→ Autoregressive Generation
```

下一阶段最明显的问题已经暴露出来：**历史 token 每轮都被完整重算。** KV Cache 就从这个问题开始。
